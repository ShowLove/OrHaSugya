# Sugya Source Relationship Analysis Prompt

You are an expert in the structure of the Babylonian Talmud.

You are given FOUR files.

FILE 1

<TRACTATE>_bundle.jsonl

This file contains the original text of the tractate.

This is the PRIMARY source.

Every conclusion must ultimately be supported by this file.

FILE 2

<TRACTATE>_sugya_analysis.json

This file contains the proposed sugya boundaries.

Do NOT redefine the sugyot.

Use these boundaries exactly.

FILE 3

<TRACTATE>_authority_analysis.json

This file contains the authority structure of each sugya, including the cited sources, source groups, source roles, authority rank, structural centrality, and direct dependencies.

Use it as a structured guide.

Always verify against the original bundle.

FILE 4

<TRACTATE>_argument_analysis.json

This file contains the reconstructed arguments, positions, participants, supporting sources, argument flow, and resolutions for every sugya.

Use it to connect each source to the correct argument and position.

Always verify against the original bundle.

Replace <TRACTATE> with the tractate name used by the project.

The required output filename is:

<TRACTATE>_source_relationship_analysis.json

Version information belongs inside the JSON through analysis_version, not in the filename.

====================================================
PRIMARY OBJECTIVE
====================================================

The purpose of this analysis is NOT to redefine the sugyot.

The purpose is NOT to reconstruct the arguments from scratch.

The purpose is NOT to perform full textual or grammatical exegesis.

Instead, reconstruct the complete RELATIONSHIP STRUCTURE of every source within each sugya.

For every source:

• determine exactly which argument it relates to

• determine exactly which position, question, objection, or resolution it affects

• determine its primary role

• explain what immediately precedes the source

• explain why the source appears at that point

• explain why this specific source was chosen

• explain HOW it introduces, supports, opposes, questions, limits, distinguishes, reframes, illustrates, applies, or resolves a position

• identify direct interactions with other sources

• identify direct dependency relationships

• explain how removing the source would affect the argument

• determine whether another source could replace it

• explain how the source contributes to the sugya as a whole

The final output must be ONE valid JSON object.

====================================================
CRITICAL RULE
====================================================

Never write generic statements.

The following are forbidden:

"This source supports the argument."

"This source advances the discussion."

"This source opposes the position."

"This source is used in the sugya."

Instead explain HOW.

A valid explanation identifies:

• the discussion immediately before the source

• the specific claim or problem the source addresses

• the source's concrete contribution

• the logical effect of that contribution

• why the argument would be weaker, different, or incomplete without it

====================================================
SOURCE ROLE
====================================================

Every source receives ONE primary role.

Choose ONE:

FOUNDATION

QUESTION

PROOF

SUPPORT

OBJECTION

LIMITATION

RESOLUTION

DIGRESSION

BACKGROUND

ILLUSTRATION

PRACTICAL APPLICATION

If a source performs secondary functions, record them in additional_explanations or source_interactions rather than assigning multiple primary roles.

====================================================
RELATIONSHIP TO ARGUMENT
====================================================

For every source identify:

argument_number

The argument from <TRACTATE>_argument_analysis.json to which the source belongs.

position_reference

A concise description of the position, question, objection, or resolution affected by the source.

relationship_to_argument

Use this structure:

{
  "summary": "",
  "details": ""
}

summary:

A concise statement of the source's relationship to the argument.

details:

1–5 sentences explaining:

• what immediately precedes the source

• what claim, question, or difficulty the source addresses

• what the source contributes

• how that contribution changes the logical position of the argument

• why the argument would be weaker or incomplete without it

Do NOT merely repeat the source role.

====================================================
RELATIONSHIP ANALYSIS
====================================================

Every source must include:

{
  "primary_explanation": "",
  "additional_explanations": []
}

primary_explanation:

1–5 sentences explaining the source's principal relationship to the argument in this sugya.

additional_explanations:

Include up to THREE additional distinct ways the source contributes.

Each item should be one concise sentence.

Return [] if there are no additional distinct contributions.

Do not split one explanation into artificial subpoints merely to fill the array.

====================================================
WHY THIS SOURCE WAS CHOSEN
====================================================

For every source explain why this specific source is useful here.

Consider:

• its authority

• its wording

• its legal category

• its similarity to the present case

• its contrast with another source

• its ability to resolve an ambiguity

• its function as a known precedent

• its role as a practical illustration

Do not perform full Hebrew or grammatical analysis here.

Detailed textual interpretation belongs to Exegesis Analysis.

Use one to three concise sentences.

====================================================
RELATIONSHIP TO SUGYA
====================================================

For every source include:

{
  "summary": "",
  "details": ""
}

summary:

A concise statement of the source's contribution to the sugya as a whole.

details:

1–3 sentences explaining whether the source:

• establishes the sugya's foundation

• develops a major branch

• creates a challenge

• forces a distinction

• supplies a resolution

• illustrates a conclusion

• forms a temporary digression

• connects the discussion back to its central issue

====================================================
SOURCE INTERACTIONS
====================================================

Record explicit and structurally important interactions between sources.

Use:

"source_interactions": [
  {
    "other_source": "",
    "interaction_type": "",
    "details": ""
  }
]

Choose an interaction_type such as:

Supports

Opposes

Questions

Clarifies

Limits

Distinguishes

Reinterprets

Harmonizes

Depends On

Resolves

Applies

Illustrates

Supersedes

details must explain the concrete interaction.

Record direct interactions only.

Do not attempt to construct a complete graph of every possible relationship.

====================================================
DEPENDENCY RELATIONSHIPS
====================================================

For every source determine whether its function directly depends on another source.

Examples:

A Baraita explains the Mishnah.

An Amora interprets a Baraita.

A verse supplies proof for an Amoraic position.

A story illustrates a halakhic conclusion.

Use:

{
  "depends_on": "",
  "dependency_type": "",
  "dependency_details": ""
}

Use null values when no direct dependency exists.

Record only the direct dependency.

====================================================
ARGUMENT EFFECT
====================================================

For every source include:

{
  "if_removed": "",
  "replacement_possible": true,
  "replacement_reason": "",
  "importance_to_argument": ""
}

if_removed:

Explain how the argument would change if the source were absent.

replacement_possible:

Use true or false.

replacement_reason:

Explain whether another source in the sugya could perform the same function.

importance_to_argument:

Choose ONE:

Essential

Major

Moderate

Minor

Illustrative

This importance measures argumentative function, not normative authority.

====================================================
SOURCE GROUPS
====================================================

Preserve useful source groupings from Authority Structure Analysis where possible.

Examples:

Biblical Foundations

Mishnaic Foundations

Baraitot

Primary Amoraic Debate

Supporting Proofs

Objections

Resolutions

Aggadic Digression

Practical Applications

Create as few groups as necessary.

Do not produce one unstructured flat list when meaningful groups exist.

====================================================
SUGYA-LEVEL RELATIONSHIP SYNTHESIS
====================================================

After analyzing every source in a sugya, explain how the sources collectively create the discussion.

Include:

{
  "central_relationship_pattern": "",
  "relationship_between_source_groups": "",
  "source_driven_argument_progression": "",
  "most_important_dependency": "",
  "effect_of_digressions": "",
  "collective_contribution": ""
}

central_relationship_pattern:

Identify the dominant pattern, such as foundation → objection → distinction → resolution.

relationship_between_source_groups:

Explain how the major source groups relate.

source_driven_argument_progression:

Explain how successive sources move the argument forward.

most_important_dependency:

Identify the most consequential direct dependency.

Use null if no dependency is especially important.

effect_of_digressions:

Explain how temporary source clusters affect the main discussion.

Use null if no digression is present.

collective_contribution:

Explain how the full set of sources produces the sugya's structure or conclusion.

Keep each field concise.

====================================================
KEEP THE JSON COMPACT
====================================================

Avoid long quotations.

Do not reproduce the Gemara.

Use concise explanations.

Use 1–3 sentences for most details fields.

Use up to 5 sentences only for relationship_to_argument.details and relationship_analysis.primary_explanation when necessary.

Include no more than three additional_explanations.

Do not duplicate full argument summaries already available in <TRACTATE>_argument_analysis.json.

Do not duplicate full textual or grammatical analysis that belongs in <TRACTATE>_exegesis_analysis.json.

====================================================
FINAL REVIEW
====================================================

Perform a second pass before producing the JSON.

Verify:

• every cited source has been captured

• every source is connected to the correct argument

• every source has one primary role

• every relationship explains HOW the source performs its role

• every source interaction names the other source and explains the interaction

• every dependency is direct

• every if_removed field explains a concrete effect

• every replacement_possible value is justified

• digression sources are not incorrectly treated as central

• no field merely repeats a generic role label

• no detailed Hebrew, grammatical, or hermeneutic analysis has been duplicated from the Exegesis stage

Only after this review produce the final JSON.

The final output MUST be valid JSON only.

Return or save the completed output as:

<TRACTATE>_source_relationship_analysis.json
