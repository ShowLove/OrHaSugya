STAGE

Argument Structure Analysis

INPUTS

1. <TRACTATE>_sugya_analysis.json
2. <TRACTATE>_bundle.jsonl

OUTPUT

<TRACTATE>_argument_analysis.json

Populate only:

outputs.argument_analysis

from OrHaSugya_OutputSchema.json. Return that object as the root output object.

OBJECTIVE

Reconstruct the complete argument structure of every supplied sugya without
redefining its boundaries.

ANALYSIS RULES

1. Analyze every sugya independently within its supplied start and end locations.
   The bundle controls; the authority analysis is a structured guide.

2. Identify every distinct investigation, disagreement, proof sequence, challenge,
   conceptual distinction, resolution, practical application, or narrative argument.
   A sugya may contain zero, one, or many arguments.

3. For each argument, populate every applicable schema field for:
   issue, question, sides, positions, supporting rabbis, supporting sources,
   reasoning, underlying principles, strength, argument flow, objections,
   resolutions, confidence, and source relationships.

4. Use the shared summary/details structure exactly where defined by the schema.
   Follow the bounded detail limits in OrHaSugya_AnalysisStandards.json.

5. Position details must state the actual claim in context, not merely name the view.
   Reasoning must explain how the evidence leads to the claim.
   Underlying principles must identify the broader legal, logical, ethical,
   theological, or interpretive rule doing the work.

6. Distinguish:
   - the question being investigated;
   - each side's claim;
   - evidence for each side;
   - objections and replies;
   - the final status;
   - the accepted position, if any;
   - remaining disagreements;
   - practical consequences.

7. Source relationships in this stage should remain compact but specific.
   Identify the source, role, affected argument number, and concrete relationship.
   Full source-to-source relationship analysis belongs to the next stage.

8. Identify all rabbinic participants and their actual role. Do not infer support
   merely because a rabbi is mentioned.

9. For primarily aggadic or narrative material, fully populate the schema's aggadic
   analysis: story, characters, conflict, lesson, principles, practical takeaway,
   and relationship to the sugya. Do not force a halakhic resolution.

10. Resolution status must reflect the text. Do not convert an unresolved exchange
    into consensus or accepted halakhah. Every resolution must also identify the
    exact hierarchy target or targets it resolves.


HIERARCHICAL NUMBERING

Every level of the argument hierarchy must be explicitly numbered:

• sugya_number
• argument_number
• side_number
• position_number

Numbering rules:

• sugya_number is inherited from <TRACTATE>_sugya_analysis.json.
• argument_number restarts at 1 inside each sugya.
• side_number restarts at 1 inside each argument.
• position_number restarts at 1 inside each side.

Do not omit a number because there is only one item.

Every position must therefore be machine-addressable as:

sugya:X → argument:X → side:X → position:X

====================================================

RESOLUTION TARGETING

Every resolution must explicitly identify what it resolves.

Populate resolution.resolution_targets exactly as defined in OrHaSugya_OutputSchema.json.

Each resolution target must include:

• sugya_number
• argument_number
• side_number
• position_number
• target_level
• resolution_action
• details

target_level must be one of:

Sugya
Argument
Side
Position

resolution_action should use the most precise description supported by the text, such as:

Accepts
Rejects
Limits
Distinguishes
Reconciles
Clarifies
Supersedes
Applies
Leaves Unresolved
Preserves Multiple Opinions
Other

Examples:

sugya:3 → argument:2 → side:1 → position:1

means the resolution acts specifically on Position 1 of Side 1 of Argument 2 in Sugya 3.

sugya:3 → argument:2 → side:0 → position:0

means the resolution applies to Argument 2 as a whole.

sugya:3 → argument:2 → side:2 → position:0

means the resolution applies to Side 2 as a whole.

Use 0 only when a lower level is genuinely not the target.

If a resolution affects multiple positions, sides, arguments, or the sugya as a whole,
create one resolution_targets entry for each affected target.

Do not collapse multiple targets into one vague description.
